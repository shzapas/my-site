Умный анализ запасов

🎯 Что это?

Инструмент для анализа товарных запасов, который объединяет данные из 10+ отчетов в единую сводную таблицу с возможностью редактирования, фильтрации и выгрузки.

🚀 Как это работает?

1. 📁 Загрузка данных
  • Нажмите "Загрузить все отчеты из папки" — система сама найдет и загрузит все нужные файлы
  • Или загружайте отчеты по одному через меню "Загрузить Excel-отчеты"
  • 🆕 Отчёты распознаются по содержимому (колонкам) — имена файлов больше не критичны. Для «Недопоставок» и «ЭКСПО» пока работает распознавание по имени (Недопоставки.xlsx, ЭКСПО.xlsx).
  • Возле каждого загруженного отчёта — счётчик свежести 🕒 (дата файла и возраст: сегодня / вчера / N дн. назад).
2. 🧮 Расчет сводной таблицы
  • Нажмите "ВЫЧИСЛИТЬ" — и все данные объединятся в одну таблицу
  • Система автоматически: рассчитывает запас в днях, определяет критические позиции (<7 дней), выделяет УТО-позиции, отмечает Бест-товары, показывает товары в пути
  • Пустые ячейки заменяются на 0 для корректных расчётов
  • Если товар есть, но продаж нет — запас = 999 дней
3. 🔍 Фильтрация
  • По магазину, отделу, подотделу, типу
  • По диапазону дней (запас, в пути)
  • По ТОП (1, 2, 0)
  • Поиск по артикулу, штрихкоду, поставщику — ищет по всем магазинам
  • Если артикул не найден — показывает понятное сообщение
  • Быстрые фильтры (УТО, Бест, Мины, ПУТО) показывают понятное сообщение, если товаров нет
4. ✏️ Редактирование (онлайн-режим)
  • Включается кнопкой "Онлайн-редактор"
  • Можно менять "Вид минимума" и "Кол-во проектов"
  • Изменения сохраняются и выгружаются в специальный файл
  • Ctrl+Z — отмена последнего действия
5. 📊 Аналитика
  • Переключитесь на вкладку "Аналитика"
  • Вы увидите количество товаров по категориям (критический запас, УТО, Бест и т.д.)
  • Кликабельные карточки — нажмите на любую, и выгрузится список товаров
  • Топ-10 проблемных товаров и сводку по магазинам
6. ⬇️ Выгрузка
  • "ВЫГРУЗИТЬ ВСЕ" — полная сводная таблица в Excel
  • "ВЫГРУЗИТЬ MIN Custom" — только измененные позиции для поставщиков
  • Из аналитики — выгрузка ТОП-10 или ВСЕХ товаров по категории
7. 🏪 Быстрый переход в MagPortal
  • Двойной клик по строке или артикулу — открывается карточка товара
  • Кнопка 🏪 рядом с артикулом — открытие в MagPortal
  • Enter при наведении на строку — открытие в MagPortal
8. 🚨 Вкладка "Аномалии"
  • Автоматическое сканирование 3 типов ошибок
  • Фильтр по типу ошибки с возможностью выбора
  • Кнопка "Предложить исправления" с модальным окном
  • Статистика ошибок по магазинам
  • Выгрузка рекомендаций для поставщиков
  • При нажатии "Принять" — артикул записывается в экспорт с комментарием "аномалия"

🎯 Вкладка "МИНЫ" — логика рекомендаций v2.11

Продажи в день = Отгружено за 7 дн ÷ 7 (в отчёте это недельная сумма!).

MIN 441 = Вместимость × 90%«Наполни полку» — ограничен полкой
MIN 500 = продажи/дн × Дниобычные — 14 дн, 20/80 и Бест — 22 дн; × сезонность × пики 1.2. Полкой НЕ ограничен
  • Продаж нет → снять MIN. Иначе: если MIN 500 ≤ MIN 441 — берём 441, если больше — берём 500 (ходовой товар, излишек в подсобке).
  • Округление — всегда вверх (MIN — минимальный порог).
  • Пример: отгрузка 14.7 за нед → 2.1/дн; 441 = 50×90% = 45; 500 = 2.1×14 = 30. 30 < 45 → MIN 441 = 45.
  • Метка 🏷️ = 20/80, ⭐ = Бест — для них свой срок 22 дн.
  • Статусы: 🟢 установить · 🟡 повысить · 🔴 понизить · ✅ норма · ⚪ снять.
  • Настройки (дни, % полки, сезонность, пики) — сверху вкладки.

📊 Вкладка «Аналитика» 1. «🔄 Обновить» после расчёта. 2. Карточки — клик = выгрузка списка. 3. Топ-10 проблемных — выгрузка ТОП-10 или ВСЕ. 4. Сводка по магазинам — где дефицит, где избыток.
🚨 Вкладка «Аномалии» 1. «🔍 Сканировать». 2. Выберите типы ошибок галочками. 3. «💡 Предложить исправления» → примите нужные «✅ Принять». 4. Выгрузите рекомендации для поставщиков. Принятое попадёт в «ВЫГРУЗИТЬ MIN Custom».
🎯 Вкладка «МИНЫ» 1. Сначала «🧮 ВЫЧИСЛИТЬ» на Таблице. 2. Проверьте настройки (дни, % полки, пики). 3. «🧮 РАССЧИТАТЬ». 4. Фильтруйте чипами (MIN 441 / 500 / Снять / Повысить / ⭐). 5. Применяйте по одной «✅» или «✅ ПРИМЕНИТЬ ВСЕ». Колонка «Гамма» и тег 🆕 — новинки/вновь открытые артикулы: MIN, возможно, не нужен.
🚚 Вкладка «ПУТО/УТО» 1. Слева выберите магазин-получатель + подотделы. 2. Настройте правила (горизонт, порог, локальная группа). 3. «🚚 РАССЧИТАТЬ». 4. Добавляйте «➕» в заявку. 5. «📦 Быстрая сборка» — проверьте разбивку по донорам и суммы DPAC → у каждого донора «⬇️ Шаблон» (CSV только его артикулов). 6. «🧾 Сопроводиловка» — Excel на согласование. История заявок — «🕘».
🟠 УТО и ПУТО — в чём разница УТО — уже упущенная выручка (факт из отчёта). ПУТО — прогноз потерь вперёд: продажи/дн × дефицитные дни × Цена DPAC. В ПУТО/УТО приоритет и сортировка идут по сумме УТО+ПУТО.
🔁 Вкладка «МС/ТС» Обмен мёртвым/токсичным стоком между магазинами (замена макроса). 1. Выберите магазин-донор (подставится из левого фильтра). 2. «🔁 РАССЧИТАТЬ» — для каждого МС/ТС-товара найдутся магазины, где он продаётся и запаса меньше. 3. «➕» — в общую заявку, дальше «📦 Быстрая сборка» / «🧾 Сопроводиловка» на ПУТО/УТО.

🎯 Автоматический расчёт рекомендаций MIN

🎯 Настройки рекомендаций MIN
Логика: MIN 441 = вместимость × % полки. MIN 500 = продажи в день × дней (× сезонность × пики). Для статусов 20/80 и Бест — свой срок «20/80 и BEST». Если продаж нет — рекомендация «снять MIN». Тип 441 выбирается, когда хватает полки, иначе 500. 🚚 «Учитывать запас и срок поставки»: если (запас + в пути) покрывает продажи дольше, чем срок подвоза + срок MIN, — MIN не нужен (избыток), рекомендация не меняет текущее значение.

Кнопка «✅» записывает рекомендацию как правку — она попадёт в «ВЫГРУЗИТЬ MIN Custom». 🚚 Связка с ПУТО/УТО: если артикул стоит в заявке на трансфер, строка подсвечивается голубым — MIN, возможно, не нужен. Подсветка появляется после «🧮 РАССЧИТАТЬ» на вкладке ПУТО/УТО (заявка хранится до очистки). «≈ N дн» в колонке Кол-во — на сколько дней продаж хватит рекомендуемого MIN.

🚚 ПУТО/УТО — кандидаты на трансфер

⚙️ Как настроить расчёт — короткая инструкция (нажмите, чтобы раскрыть)
1️⃣ Загрузите выгрузки (ГАММА по всем магазинам-донорам и получателям, УТО, поставки) → «🧮 ВЫЧИСЛИТЬ» на вкладке Таблица.
2️⃣ Горизонт, дн (15) — на сколько дней вперёд обеспечиваем получателя: К перемещению = 15×СДО − запас − в пути.
3️⃣ Порог запаса получателя (10 дн) — если товар в магазине закончится раньше, чем через 10 дней, магазин попадает в кандидаты.
    • Покрытие = Запас, дн. (на сколько дней хватит остатка при текущих продажах). Пример: остаток 7 шт, продаём 1 шт/дн → покрытие 7 дн ≤ 10 дн → кандидат.
    • Если покрытие больше порога (например 12 дн) — товара пока хватает, магазин в расчёт не берётся.
    • Дополнительно проверяем поставку: если заказ уже едет и придёт ≤ «Ждать поставку (2 дн)», и после неё запаса хватит — перемещение не нужно, строка отсеется.
4️⃣ Ждать поставку (2 дн) — см. пункт 3️⃣: сколько дней ещё можно ждать приход заказа, прежде чем ехать за товаром в другой магазин.
5️⃣ Макс. доля донора (50%) — защита донора от разорения, работает в два шага:
    • Шаг А. Донор обязан оставить себе «неприкосновенный запас» = max(2; 15×СДО) — то есть либо минимум 2 шт, либо запас на 15 дней его собственных продаж (что больше). Пример: донор продаёт 3 шт/дн → оставит себе max(2; 45) = 45 шт.
    • Шаг Б. Кроме того, донор отдаст не более 50% своего остатка (чтобы не оголять полку вдвое).
    • Итог: «Передать, шт» = меньшее из «сколько нужно получателю» и «сколько донор может отдать» (Шаг А и Шаг Б). Донор показывается в трёх отдельных колонках: «Донор» (номер магазина), «Запас донора» (его текущее покрытие, дн / остаток, шт) и «Остаток донора» (что останется ПОСЛЕ передачи — дн / шт); красным 🛡️, если донору осталось меньше 14 дн.
6️⃣ Высокий приоритет от (10 000 ₽) — кандидаты с УТО+ПУТО выше суммы помечаются 🔴, остальные 🟡.
7️⃣ Локальная группа (8, 92, 147, 165, 258) — магазины, между которыми возим в первую очередь; галочка «Только локальные доноры» оставляет лишь их. Галочка «Скрыть товары с датой AVS» убирает из кандидатов товары с AVS.
8️⃣ Получатель — фильтр по магазину-получателю: берётся из фильтра магазина основной панели и обновляется сразу при его смене (без пересчёта). Фильтры основной панели (подотдел, тип, ТОП, дни) применяются и к получателям, и к донорам; фильтр «Магазин» действует только на получателей — доноры ищутся по всем загруженным магазинам.
9️⃣ Нажмите «🧮 РАССЧИТАТЬ» → таблица отсортирована по стоимости DPAC (сначала дорогие) → клик по заголовку меняет сортировку → добавляйте нужные строки «➕» в заявку.
🔟 Далее: «📦 Быстрая сборка» — заявка по магазинам-донорам с суммами DPAC; в шапке каждого донора кнопка «⬇️ Шаблон для магазина N» — CSV (Артикул;Кол-во) только с его артикулами, грузите каждый файл под своего донора. «🧾 Сопроводиловка» — Excel для согласования с итоговой суммой.

🟠 Как считается ПУТО (потенциальный УТО), ₽
• УТО (факт) — выручка, уже упущенная за прошлый период (из отчёта УТО).
• ПУТО (прогноз) — сколько потеряем впереди, если ничего не переместим: ПУТО = продажи/дн × дефицитные дни × Цена DPAC, где дефицитные дни = Горизонт (15) − текущее покрытие.
• Пример: продаём 0.7 шт/дн, покрытие 2.2 дн, горизонт 15 дн → дефицитных дней 12.8 → ПУТО = 0.7 × 12.8 × DPAC.
• В колонке «УТО+ПУТО ₽» показывается сумма с разбивкой (фиолетовым факт, оранжевым прогноз) — по ней же считается приоритет 🔴/🟡 и сортировка.
🚚 Правила трансферов (по памятке)
Логика (флоучарт коллег): получатель = СДО>0, запас ≤ 10 дн, есть УТО/ПУТО. Есть заказ и ≤ 2 дн до поставки (и после неё запаса хватит) — ждём. Донор = с продажами, один с наибольшим запасом (локальные приоритетны); оставляет себе max(2; 15×СДО) и не более 50% остатка. К перемещению = min(15×СДО − запас − в пути; может дать). Приоритет: УТО+ПУТО ≥ 10 000 ₽ — высокий.

# Магазин Артикул Наименование Гамма УТО+ПУТО ₽ Приоритет Остаток СДО Покрытие, дн Поставка Донор Запас донора Остаток донора Передать, шт Стоимость, ₽ (DPAC) ➕
🔽 Сортировка: кликните по заголовку любой колонки — первый клик «от большего к меньшему», повторный — наоборот. По умолчанию — «Стоимость, ₽ (DPAC)» по убыванию (сначала самые дорогие перемещения).
«➕» добавляет артикул в заявку. Выгрузка для загрузчика дочерних заказов (Артикул;Количество, без ЛМ-кода) — кнопкой «⬇️ Шаблон для магазина N» в «📦 Быстрой сборке», у каждого магазина-донора свой файл. Колонка «Стоимость, ₽ (DPAC)» = количество к перемещению × «Сумма Цена DPAC» из отчёта ГАММА (стоимость товара в ДЕПАК).

🔁 МС/ТС — обмен мёртвым и токсичным стоком между магазинами

💡 Горизонт получателя, дн — на сколько дней продаж обеспечиваем получателя: «Передать, шт» = min(запас донора; горизонт × СДО получателя − его остаток − в пути).
💡 Макс. покрытие получателя, дн — получателем становится только магазин, где артикул продаётся и его текущий запас покрывает меньше этого числа дней (иначе товар там и так лежит).
💡 Остаток получателя — текущий запас магазина-получателя (не донора!); строка «после: N шт» — его будущий сток после передачи.
⚙️ Как работает обмен МС/ТС (нажмите, чтобы раскрыть)
1️⃣ Выберите магазин-донор — тот, у кого по товарам стоят метки МС (мёртвый сток) и/или ТС (токсичный сток). По умолчанию подставляется магазин из левого фильтра «Магазин» и обновляется при его смене.
2️⃣ Для каждого такого товара таблица ищет получателей — другие загруженные магазины, где тот же артикул продаётся (СДО > 0) и его запас меньше (покрытие ≤ «Макс. покрытие получателя, дн»). Сначала — где покрытие наименьшее.
3️⃣ «Передать, шт» — сколько донор может отдать: min(запас донора; горизонт×СДО получателя − его запас − в пути), но не меньше 1. Число можно править вручную.
4️⃣ Кнопка «➕» добавляет позицию в общую заявку на трансфер (вкладка 🚚 ПУТО/УТО) — дальше «📦 Быстрая сборка» и «🧾 Сопроводиловка» работают как обычно, донором будет магазин с МС/ТС.
5️⃣ У мёртвого стока донора нет продаж, поэтому его покрытие после передачи показывается как «∞» — товар у него всё равно лежит без движения.
6️⃣ Это замена ручного макроса «прогнать список МС/ТС по всем магазинам и посмотреть, где запас меньше» — теперь всё считается одной кнопкой.
